Getting Started 5 min

From a fresh account to your first published app. No installation, no setup — Stackly runs entirely in the browser.

Create your first project

After creating an account, you land on the dashboard. Every app you build is a project: it bundles pages, components, data collections, and workflows in one place.

  1. Click "New Project" on the dashboard, or press N from anywhere.
  2. Pick a starting point — one of 120+ templates, or a blank canvas if you prefer to compose from scratch.
  3. Name your project and choose a workspace. Free plans include one workspace with up to 3 projects.
  4. Open the builder — you're dropped straight onto the canvas with the template's pages ready to edit.
Tip Starting from a template that's roughly 70% right is almost always faster than a blank canvas — every template's pages, data model, and workflows are fully editable.

Tour the workspace

The builder has three zones: the component library on the left, the canvas in the center, and the property inspector on the right. The top bar holds device preview, undo/redo, version history, and the Publish button. Everything you do on the canvas autosaves within seconds.

Builder Basics

The canvas is a real, live version of your app — what you see is exactly what ships.

Selecting, moving & resizing

Click any element to select it; drag to move, pull the handles to resize. Elements snap to a 8-pixel grid and to the edges of nearby components. Hold Alt while dragging to duplicate, and Shift to constrain movement to one axis.

Versions & history

Every change is recorded. Open History in the top bar to scrub through past states, name important versions ("pre-launch", "v2 pricing"), and restore any of them in one click. Restoring never destroys newer work — it simply creates a new version at the top of the stack.

Heads up History is kept for 30 days on Free, 6 months on Pro, and forever on Business. Named versions are never pruned on any plan.

Components

120+ building blocks, from buttons to full data tables. Drag them from the library; configure them in the inspector.

Layout components

Containers, columns, and sections control structure. Containers stack their children with configurable gap and padding; columns split space by ratio and collapse gracefully on mobile. Use sections for full-width bands with their own background.

Data components

Tables, lists, cards, and charts bind directly to collections. Point a table at your Orders collection and pick the columns — sorting, pagination, and empty states are handled for you. Charts (line, bar, donut) accept the same bindings plus an aggregation: count, sum, or average per period.

Tip Any data component can be filtered by the logged-in user — set the filter to created_by = Current User to build "my items" views with zero logic.

Form components

Inputs, dropdowns, checkboxes, file uploads, and date pickers combine into forms that write to collections. Validation rules (required, email, min/max, regex) are set per field in the inspector, and every form gets a configurable success action: show a message, redirect, or trigger a workflow.

Data & Collections

Every project ships with a built-in database. Collections are tables; fields are columns; relations connect them — all managed visually.

Creating collections

Open the Data tab and click "New Collection". Add fields with types: text, number, date, boolean, select, file, or relation. A relation field links records across collections — for example, each Order belongs to one Customer, and a customer has many orders.

collection: orders — schemaread-only
Orders
├─ number      auto-increment   // ORD-1042
├─ customer    relation → Customers
├─ items       relation → Products (many)
├─ status      select ["pending", "paid", "shipped"]
├─ total       number (currency)
└─ created_at  date auto

Permissions

Each collection has row-level rules per role: who can create, read, update, and delete. Rules can reference the current user, so "users edit only their own records" is a single dropdown, not a policy engine.

Important New collections default to workspace members only. Before publishing a public app, review the read rule on every collection the public pages bind to.

Importing data

Import CSV or Google Sheets from the collection menu. Stackly maps columns to fields automatically, flags type mismatches before anything is written, and imports up to 50,000 rows per file on Pro plans.

Workflows

Automate what happens around your data: send emails, call webhooks, update records — visually, on a logic canvas.

Triggers

Every workflow starts with a trigger: a record is created/updated/deleted, a form is submitted, a schedule fires (hourly to monthly), or an incoming webhook is received. One workflow can have many steps but exactly one trigger.

Steps & conditions

Chain steps with drag-and-drop: send email, update record, create record, call webhook, delay, and branch. Branches evaluate conditions on trigger data — "if total > 500, notify the account manager; otherwise send the standard receipt."

  1. Add a trigger — e.g. Record created in Orders.
  2. Add a branch — condition: total > 500.
  3. On the "yes" path, add Send email → template "vip-order" to the sales team.
  4. Test with sample data using the Run panel, then toggle the workflow to Live.
Tip Every run is logged with its full step-by-step output under Workflows → Runs — the first place to look when an automation misbehaves.

Publishing

One click deploys your app to a global edge network with SSL. Custom domains, rollbacks, and staging included.

Your first publish

  1. Press Publish (or Ctrl + Shift + P). Stackly validates broken links, missing permissions, and unbound components first.
  2. Review the checklist — warnings are advisory, errors block the deploy until fixed.
  3. Go live at yourapp.appflow.site. Deploys typically complete in under 30 seconds worldwide.

Custom domains

On Business plans, open Settings → Domains, add your domain, and point a CNAME record at edge.appflow.io. Certificates are provisioned and renewed automatically; most domains verify within minutes.

DNS note If your registrar proxies traffic (orange-cloud style), disable the proxy for the verification record until the certificate is issued, then re-enable it.

Rollbacks

Every publish creates an immutable deployment. From Settings → Deployments you can preview any past deployment on a temporary URL and promote it back to production instantly — no rebuild required.

Integrations

Native connections to the tools you already use, plus a REST API and webhooks for everything else. See the full catalog on the integrations page.

Connecting a native integration

Go to Settings → Integrations, pick a provider (Stripe, Slack, Mailchimp, Google Sheets, Shopify, Zapier…), and authorize with OAuth. Once connected, the provider's actions appear as workflow steps and its data sources appear in the binding picker.

REST API

Every collection is addressable over HTTPS with an API key scoped to your project. Keys are managed under Settings → API; requests are rate-limited to 120/min on Pro and 600/min on Business.

GET /v1/collections/orders/recordscurl
curl https://api.appflow.io/v1/collections/orders/records \
  -H "Authorization: Bearer af_live_xxxxxxxxxxxx" \
  -G -d "filter[status]=paid" -d "sort=-created_at" -d "limit=25"

# → 200 OK

Keep keys secret API keys grant the access level of the role they're scoped to. Never embed a live key in client-side code — use a workflow webhook as a proxy instead.

Account & Billing

Plans, seats, invoices, and everything about managing your Stackly subscription.

Plans & upgrades

Compare plans on the pricing page. Upgrades apply immediately and are prorated; downgrades take effect at the end of the billing period. Apps above a lower plan's limits are paused, never deleted, and resume the moment you upgrade again.

Invoices & payment methods

Under Billing you can update cards, switch between monthly and annual billing (annual saves 20%), download PDF invoices, and add a VAT/tax ID that appears on future invoices.

Tip Nonprofits and accredited educators get 50% off Pro — contact us with your documentation and we'll apply it within one business day.

Team & seats

Business workspaces bill per editor seat; viewers are always free. Owners manage roles under Settings → Team: Owner, Editor, and Viewer. Transferring workspace ownership requires email confirmation from both parties.
